# Q3D 캐릭터 에셋 적용 검토 (SWI 저장소 · Unity 검수본)

대상: `gsh8792-lgtm/SWI` — `Deliverables/CleanCharacter/Character.glb` (사제 계열 여성 캐릭터, 4K 텍스처 포함)

## 1. 에셋 정보

| 항목 | 값 |
|---|---|
| 형식 | GLB (텍스처 내장) · FBX + 4K PNG · Blender 원본 · Unity 패키지 |
| 뼈대 | 25개 (Root·Hips·Spine·Chest·Neck·Head·팔다리·망토·치마·소매) |
| 동작 | Idle 3.0초 · Walk 1.0초 · Cast 2.0초 |
| 폴리곤 | 약 23만 삼각형, 메시 13개, 재질 1개 |
| 크기 | GLB 19.8MB |

## 2. 우리 게임에 넣는 방법

우리 게임은 캔버스 2D 단일 HTML이라 3D를 실시간으로 그리지 않는다. 대신 **3D를 미리 2D 동작 프레임으로 굽는다** (스파인/도트 게임의 "프리렌더 스프라이트" 방식).

- `tools/q3d/bake_q3d.mjs <glb> <스프라이트 이름> [각도] [프레임 높이] [머리 배율]`
  - 헤드리스 브라우저 + three.js로 정사영 렌더
  - **동작은 에셋 클립을 쓰지 않고 직접 만들었다** (`tools/q3d/motions.mjs`): 뼈 회전 키프레임을 코드로 짜서 굽는다
    - 대기 8(숨쉬기·고개·손) · 걷기 8(다리 교차·팔 반대 흔들기·몸 들썩임) · 공격 6(오른손을 모았다 밀어내기) · 시전 10(두 손을 모아 들어 올렸다 펼치기) · 피격 4(뒤로 젖혀짐) · 쓰러짐 6(무릎 꿇고 고개 떨굼, 마지막 프레임 유지)
    - 뼈 축 확인 도구: `render.html`의 `AXES()` (뼈마다 x/y/z 회전 시 끝점이 움직이는 방향)
  - **셰이딩 = SWI Unity 검수본과 동일** (기본 `unity`): `Assets/ReferenceCharacter/Shaders/ReferenceCharacterToon.shader`의 공식을 three.js로 그대로 옮김
    - 색 = 텍스처 × lerp(그늘 틴트, 1, smoothstep(0.02, 0.18, N·L)), 그늘 틴트 = 연보라 (0.78, 0.75, 0.86)을 25%만
    - 키라이트 = Unity `KeyLight` Euler(35, -30, 0) 방향, 카메라 45° 정사영 (Unity 검수 캡처와 같은 각도)
    - 원래 비율 유지(머리 배율 1.0), 색 보정·포스터화 없음, 1024px로 그려 300px 프레임으로 축소(금장식 디테일 보존), 얇은 외곽선 1.2px
  - 다른 스타일도 남겨 둠: `toon`(3단 명암 + 포스터화), `pbr`(실사 음영)
  - 처음 버전이 이상해 보였던 이유: 따뜻한 조명 + 채도 보정으로 흰 옷이 주황빛, 머리 1.55배 확대로 비율 왜곡, 240px + 포스터화로 장식 뭉개짐
  - **머리 배율**: Head 뼈를 키우는 옵션 (치비 시험용, 지금은 1.0 = 원본)
  - 결과: `src/js/02b_sprite_sheets.js` (webp 시트 약 700KB, 데이터 내장)
- 게임 쪽: `drawSprite`가 시트가 있으면 상태에 맞는 프레임을 그린다 (전투: 이동 = 걷기, 평타 = 공격, 스킬 = 시전, 맞으면 피격, 쓰러지면 쓰러짐 자세로 남음 · 던전/마을: 걷기/대기). 초상화는 첫 프레임 머리 부분. 미리보기: `test-output/q3d_motions.gif`
- **타이틀 화면 "3D 에셋(보리): 켬/끔"** 으로 바꿔 볼 수 있다 (기본 끔).

## 3. 결과 (`node tools/dev/q3d_shot.mjs` → `test-output/q3d_*.png`)

- 기술적으로는 **바로 교체 가능**. 전투·던전·마을에서 동작 6종이 돌아가고, 빌드 크기는 약 +700KB.
- 3D 원본을 매번 실시간으로 그리지 않으므로 모바일 성능 영향은 없다 (23만 폴리곤이 문제되지 않음).

## 4. 문제점 — 화풍

| | 지금 치비(코드 드로잉) | Q3D 캐릭터 |
|---|---|---|
| 등신 | 2.5등신, 큰 머리·큰 눈 | 6~7등신 사실 비율 (전투에서 1.32배 크게 그려 얼굴이 보이게 함) |
| 질감 | 평평한 채색 + 잉크 선 | Unity와 같은 부드러운 툰 셰이딩, 금장식 디테일 |
| 노출 | 사제복 (전신 가림) | 가슴·다리가 강조된 의상 — 게임 등급과 마케팅 범위 확인 필요 |
| 108px 크기에서 | 얼굴 표정이 읽힘 | 얼굴이 작아 표정이 거의 안 보임 |

한 명만 바뀌면 파티 안에서 혼자 다른 게임 캐릭터처럼 보인다.

## 5. 권장

1. **전원 3D 프리렌더로 갈지, 지금 치비 화풍을 유지할지 먼저 정한다.** 섞어 쓰는 건 비추천.
2. 3D로 간다면: 모델링 단계에서 치비 비율(머리 2~2.5배, 다리 짧게)로 만든 모델이 필요하다. 지금 모델은 머리만 키우는 것으로는 한계가 있다.
3. 동작 6종은 직접 만든 것으로 대체됨. 다만 망토·치마가 다리 뼈에 묶여 있어 걸을 때 크게 펄럭인다 — 모델에서 치마 웨이트를 다듬으면 더 좋아진다.
4. 굽는 도구는 그대로 재사용: 새 GLB를 넣으면 시트가 다시 만들어진다.
