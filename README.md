## 재의 서약 · Ashen Oath

위 두 줄은 기존 저장소 소개를 보존한 것입니다. `AshenOath/`에 새로운 Unity 횡스크롤 파티 RPG를 추가했습니다.

Unity 6000.6.2f1 프로젝트입니다. 첫 제작 범위는 마을과 5개 구역으로 이루어진 원정이며, 다섯 번째 구역이 보스입니다. 5개 지역 × 20개 구역의 원정 진행도 코드에 포함되어 있습니다. 지역별 독립 배경·몬스터·보스 애니메이션 제작은 후속 콘텐츠 작업이며, 100개의 서로 다른 완성 맵을 의미하지 않습니다.

### 실행

Windows 배포 폴더 전체를 압축 해제한 다음 `AshenOath.exe`를 실행합니다. 실행 파일만 따로 옮기면 안 됩니다. Unity에서 수정할 때는 Unity Hub로 `AshenOath` 폴더를 열고 `Assets/Scenes/Boot.unity`를 실행합니다.

Android 배포본은 Android 8.0 이상 ARM64용 `AshenOath.apk`입니다. 빌드와 APK v2 서명을 확인했습니다. 현재 연결된 Android 기기가 없어 실제 기기에서의 실행·발열·동시 터치·서로 다른 기기 사이 LAN 접속은 확인하지 못했습니다. iOS 빌드는 포함하지 않습니다.

처음에는 **전직·동료** 탭에서 직업을 선택하고 **원정 → 첫 원정**으로 출발합니다. 파티는 남성 주인공과 AI 동료 두 명입니다. 동료의 직업과 방침은 마을에서 정합니다.

| 조작 | 키 |
| --- | --- |
| 이동 / 점프 | A·D 또는 방향키 / Space |
| 공격 / 직업 스킬 | J 또는 마우스 왼쪽 / K |
| 회피 / 방어 | Shift / L |
| 물약 / 장비 | H / I |
| 파티 명령 / 자주 쓰는 명령 | Tab / 1~4 |
| 다음 방 / 일시정지 | E / Esc |
| 판정 영역 표시 | F3 |

게임패드의 왼쪽 스틱, A(점프), X(공격), Y(스킬), B(회피), LB(방어)를 연결했습니다. 기기별 버튼 배열 차이와 실제 휴대폰 조작은 별도 실기기 검증이 필요합니다. 일시정지 메뉴에서 터치 버튼을 표시할 수 있습니다.

### 규칙

- 한 번의 정식 원정은 20개 구역입니다. 5·10·15번째는 모닥불, 20번째는 보스입니다. 5구역 체험은 전투 → 사건 → 모닥불 → 정예 → 보스입니다.
- 사망하면 레벨, 능력치와 스킬 배분이 초기화됩니다. 영구 룬 특성과 창고는 보존합니다. 인장을 지정한 최대 2개 장비와 추가 무작위 1개를 회수하며 내구도가 65 감소합니다. 금화는 30% 잃습니다.
- 마을에서만 전직합니다. 능력치·스킬 배분은 직업별로 저장합니다. 원정 도중에는 전직할 수 없습니다.
- 장비 등급은 D → C → B → A → S → SS → SSS → R → UR → L입니다. 각 등급의 한손검·양손검·마도구·활·쌍검 5종, 총 50종 무기 정의와 10등급 갑옷이 있습니다. 마도구는 마법사와 힐러가 공유합니다.
- 22개 옵션 계열, 등급별 0~5개 중복 없는 옵션, 직업별 장착 제한, +5 강화, 수리, 제작, 창고를 구현했습니다. 무기는 계열별 공통 원화를 사용하며 등급별 50개의 독립 일러스트는 아닙니다.
- 공격 룬 12종을 주·보조 두 칸에 조합합니다. 피해·소모량·흡혈·화상·둔화·연쇄 효과가 실제 판정에 연결됩니다. 영구 특성은 피해·체력·소모 효율 세 계열입니다.

### 계산식

`무기 공격 = 기본 공격 × (1 + 0.06 × 강화) × 내구 효율`

`기초 피해 = (직업 공격 + 레벨 성장 + 힘 × 1.5 + 무기 공격) × 스킬 계수 × 룬 피해 배율 × 영구 피해 특성`

`물리 피해 = 기초 피해 × (1 + 공격 옵션) × (1 + 물리 옵션) × 100 / (100 + 방어 × (1 − 관통))`

`마법 피해 = 기초 피해 × (1 + 공격 옵션) × (1 + 마법 옵션) × (1 − 속성 저항)`

추가 화염·냉기·번개 피해에는 속성 저항을 적용합니다. 치명타와 정예·처형 조건 배율은 그 뒤에 곱합니다. 치명 확률 75%, 관통 60%, 속성 저항 75%, 소모 감소 50%, 재사용 감소 40%, 공격 속도 60%, 흡혈 12%의 상한을 둡니다. 실제 구현은 `Equipment.ComputeDamage`와 `GameSession`에 있습니다.

### 협동 테스트

Windows에서 같은 LAN의 한 명이 방을 만들고 나머지 두 명이 방장의 IPv4 주소로 참가합니다. UDP 포트는 7777입니다. 참가자는 AI 슬롯을 대체하며 방장이 전투와 진행을 계산합니다. 유료 서비스나 Relay 구독은 사용하지 않습니다. 인터넷 매칭·NAT 우회·호스트 이전은 포함하지 않습니다. 협동 세션의 결과는 개인 저장에 반영하지 않습니다. Web 미리보기에서는 이 UDP 전송을 지원하지 않습니다.

### 아트와 검수 자료

`Art/Reference`에는 사용자가 제공한 두 원본 파일을 그대로 보관합니다. `tools/reference_rig.py`는 원본 RGB를 유지하면서 배경 알파와 부위 분리를 생성합니다. 여성 동료의 기본 외형은 이 원본 리그를 공유합니다. 6명의 고유 얼굴·복장과 완전한 갑옷 레이어 세트는 아직 별도로 제작되지 않았습니다. 체형과 관절의 제작 상태는 원본 보관 여부와 구분해서 검수합니다.

`Art/Equipment`에는 ComfyUI에서 만든 무기 원화와 재현 가능한 워크플로가 있습니다. `QA`에는 규칙·전투·접속 검사 결과와 화면 증거를 저장합니다. 합격한 검사와 구현하지 않은 범위를 구분하며, 원화와 모든 애니메이션이 100% 일치한다는 인증은 하지 않습니다.

`tools/verify.ps1`로 Windows 실행 파일의 전투·성장·저장 및 3개 프로세스의 접속 검사를 다시 실행할 수 있습니다. 여섯 직업 모두 일반 공격·스킬·물약 입력으로 5개 구역과 보스를 통과하는 검사도 포함합니다. 별도의 `--smoke` 모드는 전투를 생략하고 방 전환만 검사하므로 전투 검증과 구분합니다.
